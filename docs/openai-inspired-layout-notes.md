# Elexvx 网站设计与内容发布规范

> 版本：1.1
> 更新日期：2026-09-02
> 状态：当前唯一执行规范
> 适用范围：首页、研究、能力、成果、场景、阅读、公司及后续新增页面

本规范汇总当前首页要求、现有暗色编辑式视觉原则，以及此前官网重构过程中已经确认的整改点。后续页面设计、内容发布与前端实现均以本文件为准；其他说明与本文件冲突时，以本文件为最高优先级。

## 1. 网站定位

- 宏翔商道 / Elexvx 是跨行业研发公司，官网首先是研究与技术成果入口，不是传统服务项目录。
- `Elexvx Research` 是当前可替换的研究工作名称，不代表法定机构名称。
- 采用“公司与研究双品牌”：研究承担技术叙事，公司承担主体、业务和合作承接。
- 第一优先受众是技术同行与研究人员；中文优先，必要的英文术语作为辅助标识。
- 内容主线为“研究方向 → 研发能力 → 可验证成果 → 研究发布”，并行业务保留独立入口，不替代研究主线。

## 2. 首页信息架构

首屏先回答四个问题：Elexvx 是什么、研究什么、如何工作、已经形成什么结果。首屏之后必须按以下四个独立分区组织内容，不得把四类内容混装成一个“动态”模块。

### 2.1 研究论文与技术文章

- 用于发布研究论文、技术文章、方法记录和阶段性研究结论。
- “论文”与“技术文章”必须如实标注，不得把普通文章包装成经过同行评审的论文。
- 列表至少包含标题、发布日期、摘要和明确详情入口。
- 公开内容必须具备可追溯来源；未核验内容不得进入公开列表。

### 2.2 新闻发布

- 用于发布公司新闻、研究动态、活动与正式公告。
- 新闻回答“发生了什么”，研究内容回答“发现了什么”，两者分开管理、分开呈现。
- 每条新闻必须核验发布主体、日期、事实来源、相关链接和公开口径。
- 旧站资讯保留在归档中，不自动回流首页。

### 2.3 合作案例

- 用于发布已经获得公开授权的合作案例。
- 案例必须说明合作背景、问题边界、Elexvx 的工作、验证方法、交付结果和公开边界。
- 必须区分“目标”“过程”“已交付结果”与“后续计划”，不得以计划替代结果。
- 未取得合作方授权时保留明确占位，不出现客户名称、效果数字或暗示性背书。

### 2.4 产品展示

- 用于展示自主产品、系统原型和已经形成可验证输出的项目成果。
- 每个产品至少包含名称、成熟度状态、解决的问题、核心能力、可核验依据和详情入口。
- 产品、原型、项目不得混用状态；当前首个展示项为“起重设备智能安全管理”，状态为 `PROTOTYPE`。
- 真实产品图、现场图或系统截图未确认前，可以使用标注为 `CONCEPT VISUAL` 的编辑式概念图帮助建立阅读节奏，但不得把概念图描述成真实现场、实物截图或已交付成果。

首页四分区采用稳定顺序：研究发布 → 新闻 → 合作案例 → 产品展示。公司与合作入口可位于四分区之后，但不计入四个内容发布分区。

## 3. OpenAI 式编辑栅格与圆角

版式以清晰的编辑节奏和同级内容的一致性为基准，不再用黄金比例机械划分卡片。首页同一分区中的媒体卡片使用等宽栅格、相同比例和一致的标题位置。

### 3.1 栅格与内容权重

- 桌面端同级卡片使用等宽两栏或三栏；重点内容可以独占整行，但不得与普通卡片混在同一视觉层级中任意放大。
- 图片统一采用宽幅 `16 : 10` 或方形 `1 : 1` 两种比例，同一分区只使用一种比例。
- 分区依靠大留白、背景明度和标题层级建立关系，不使用贯穿卡片的密集分割线。
- 平板及移动端改为单栏，内容顺序保持“主内容在前、辅助说明在后”，不得反转信息优先级。

### 3.2 圆角令牌

全站媒体与大区块采用接近 OpenAI 当前页面的轻圆角，按钮按交互类型区分：

| 令牌            |     数值 | 用途                           |
| --------------- | -------: | ------------------------------ |
| `radius-media`  |      8px | 桌面媒体、主视觉、底部引导区块 |
| `radius-mobile` |      6px | 移动端媒体与引导区块           |
| `radius-pill`   | 完整胶囊 | 操作按钮、筛选项与状态标签     |

- 同一层级、同一尺寸的媒体必须使用同一圆角和相同比例。
- 列表、文字分区和页脚栏目默认不加卡片外框与圆角。
- 禁止用大圆角把所有内容做成工具卡片；圆角只用于媒体容器、主引导区块和真实交互控件。
- 禁止阴影、发光和渐变描边来强化圆角；层级依靠背景明度、图片色域和留白建立。

## 4. 视觉语言

- 当前基线为黑色导航、纯黑 / 深灰画布、白色高对比文字和编辑式内容节奏。
- 直接采用 OpenAI 官网形成的黑色画布、白色高对比、编辑式排版、媒体卡片和扩展型导航语言，同时保留 Elexvx 的 Logo、名称和内容，不使用 OpenAI 的 Logo、字体文件、插画、商标图形与页面资产。
- 全站使用系统字体优先的字体栈；标题收紧字距，正文保持舒适行高。
- 只保留一个操作强调体系。当前暗色系统以白色为主要操作色，不再并列增加第二套高饱和强调色。
- 内容媒体统一使用无可识别物体的抽象渐变色域：柔和色带、模糊光场、轻微颗粒和自然过渡，不出现人物、设备、建筑、机械、球体、文字、图标或品牌标记。
- 渐变只作为文章、研究方向与项目的编辑式视觉封面，不用于按钮、边框、文字或导航装饰。
- 不使用浮夸阴影、玻璃卡片堆叠、无意义动效或大量同权重小卡片。
- 导航必须稳定、可扩展且能说明去向；桌面端使用展开目录，移动端使用可展开分组。
- 页面应通过全宽低密度分区、明确标题和横向阅读线索建立节奏。

## 5. 内容真实性与发布边界

公开内容按以下层级管理：

1. 已核验公开事实：可直接发布，并附公开来源。
2. 已核验内部材料：仅发布允许公开的摘要，并标明依据类型。
3. 合作储备或进行中事项：必须标注状态，不得写成已经完成。
4. 方案、方向和占位：必须使用明确占位文案，不得伪造产品图、客户、指标、荣誉或案例。

研究内容继续使用本地 Markdown 管线和证据字段。已发布研究内容需要 `official`、`internal` 或 `asset` 证据，并将 `verified` 设为 `true`。新闻与案例在独立内容模型完成前，首页只展示经过核验的内容或明确空状态。

## 6. 品牌与素材

- 保留 Elexvx 自有 Logo、名称和内容，不把参考对象的视觉资产当作本站品牌资产。
- Logo 必须同时维护主标、反白标、单色标、独立图形标和 favicon / touch icon；所有消费端保持一致。
- 标志禁止渐变、描边、阴影、发光、拉伸、旋转或改变字标与图形标比例。
- 研究、文章和项目封面默认使用自有抽象渐变概念视觉，并通过 `CONCEPT VISUAL` 或上下文说明其属性；真实项目照片或系统截图只有在来源、授权和内容均确认后才替换概念视觉。
- 生成视觉不得暗示真实设备、客户现场、产品形态、效果数据或合作事实。

## 7. 交互、响应式与无障碍

- 点击目标最小高度为 `44px`；键盘焦点必须可见。
- 菜单支持 `Esc` 关闭、点击外部关闭，并保持清晰的展开状态。
- 交互反馈应即时、克制、可中断；同一控件的进入与退出路径保持一致。
- `prefers-reduced-motion` 下取消大幅位移和弹性效果，保留短淡入淡出。
- `prefers-reduced-transparency` 和高对比模式下保证文字与边界可读。
- 320px 起不出现横向溢出；桌面多栏栅格在 1068px 以下逐步折叠，移动端统一为单栏。

## 8. 技术与内容架构

- 当前实现以 React + Next.js App Router 静态导出为准；旧 Astro 源码仅用于迁移参考，不参与当前构建入口。
- 早期“纯 React / Vite SSG”是摆脱 AstroWind 模板的技术方向；当前代码已经采用 Next.js 静态导出，后续不得同时维护两套生产入口。
- 新研究内容使用自研 Markdown 管线；旧混合用途文章单独归档并设置 `noindex`。
- 所有页面入口必须有真实去向，不使用空链接或仅用于视觉占位的可点击控件。
- 构建、静态导出、内容校验、响应式检查和真实浏览器检查共同构成发布门槛。

## 9. 历史整改点总表

下表为截至 2026-09-02 已确认的全部官网整改点，新增整改必须继续追加到本表。

| 编号 | 整改点                                                           | 当前规范 / 状态                                          |
| ---- | ---------------------------------------------------------------- | -------------------------------------------------------- |
| R-01 | 首页无法快速说明公司做什么、如何工作、创造什么价值、解决什么问题 | 首屏先回答定位，四个发布分区承接证据与结果               |
| R-02 | 旧站像宽泛服务目录，研发主线不清楚                               | 改为研究优先型门户，并行业务降为独立入口                 |
| R-03 | 公司与研究身份混在一起                                           | 采用公司与研究双品牌；研究名注明可替换                   |
| R-04 | 目标受众过于宽泛                                                 | 第一优先受众固定为技术同行与研究人员                     |
| R-05 | 研究方向层级不清                                                 | AI 与数据智能、工业智能与安全、LLM / AI 安全三个方向并列 |
| R-06 | 跨行业内容按服务名堆叠                                           | 统一使用“研发能力 × 行业场景”组织                        |
| R-07 | 自主产品与定制研发关系不清                                       | 两者并行呈现，均需说明问题、过程和验证结果               |
| R-08 | 首页主要行动与研究定位不一致                                     | 主要入口统一指向研究方向、技术成果和可验证内容           |
| R-09 | 产品、案例和新闻缺少独立位置                                     | 首页建立研究发布、新闻、合作案例、产品展示四个独立分区   |
| R-10 | 内容类型混排                                                     | 论文 / 技术文章、新闻、案例、产品使用独立定义与审核条件  |
| R-11 | 真实素材不足时容易出现包装性内容                                 | 使用不含具体物体的抽象渐变封面，并明确其概念视觉属性     |
| R-12 | 旧文章与新研究体系混杂                                           | 新建研究发布体系，旧文独立归档且不回流首页               |
| R-13 | 早期视觉方向不够克制、页面卡片化过重                             | 使用低密度全宽分区、系统字体、抽象渐变媒体和无阴影卡片   |
| R-14 | 视觉参考可能演变为品牌复制                                       | 只转译布局原则，保留 Elexvx 自有品牌与素材               |
| R-15 | 导航入口多但去向不明确                                           | 使用稳定一级入口 + 展开目录，所有链接具有明确目的地      |
| R-16 | 圆角数值分散且层级不一致                                         | 媒体统一使用桌面 8px、移动 6px；交互按钮使用胶囊形       |
| R-17 | 版式比例随意                                                     | 同级卡片使用等宽栅格和统一媒体比例，重点内容独占整行     |
| R-18 | Logo、favicon 与不同页面消费端可能不一致                         | 主标、反白标、图形标和图标资产统一维护                   |
| R-19 | 技术迁移方向与实际入口存在歧义                                   | 生产入口以当前 Next.js 静态导出为准，不并行维护 Astro    |
| R-20 | 缺少发布前可验证标准                                             | 将内容校验、构建、浏览器、响应式和无障碍检查列为发布门槛 |

## 10. 首页验收清单

- [ ] 四个发布分区均存在独立标题、唯一锚点和明确内容边界。
- [ ] 研究发布只显示已核验内容；论文与技术文章不混淆身份。
- [ ] 新闻和案例没有真实内容时显示明确空状态，不伪造事实。
- [ ] 产品状态、证据与素材状态可见。
- [ ] 同一分区卡片等宽、图片比例一致，1068px 以下按规则折叠。
- [ ] 媒体圆角统一为桌面 8px、移动 6px；按钮使用一致胶囊形。
- [ ] 页面视觉封面均为无具体物体的抽象渐变，不出现卡片阴影与空链接。
- [ ] 键盘焦点、点击目标、移动端排版和减弱动态偏好通过检查。
- [ ] 静态构建、内容校验和真实浏览器检查通过。

## 11. 参考边界

- [OpenAI 官网](https://openai.com/)：作为暗色编辑式页面节奏、抽象媒体、底部引导和页脚组织的视觉基准。
- [OpenAI 设计指南](https://openai.com/zh-Hans-CN/brand/)：用于明确哪些品牌资产不得复制。

本规范不授权使用任何第三方商标、字体或视觉资产。Elexvx 的设计结果必须保持独立可识别，并以内容真实性、清晰层级和长期维护为优先。
